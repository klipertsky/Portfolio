🏭 Shop-Floor AI Agent

n8n · self-initiated project

Grounded AI for Manufacturing Operations — a tool-calling agent that answers shop-floor questions from verified data only, and knows when to escalate to a human instead of guessing.

RoleAI Engineer (solo project)
Stackn8n · Google Gemini · Tool-Calling Agent Architecture · Structured Data
TypeSelf-initiated technical project, built to a real-world industry brief
The Problem
  • Manufacturers running cabinet and panel production often keep production data — specs, workstation routing, standard operating procedures — disconnected from the actual shop floor, leaving operators without a fast way to confirm the right part, requirements, and next step.
  • A general-purpose AI answering manufacturing questions can confidently invent an answer it doesn't actually know — a machine setting, a tooling parameter, a safety step — which in production isn't a minor bug, it's a liability.
  • The real challenge wasn't "can an AI answer questions about parts" — it was whether an AI can answer reliably, cite its sources, and know when to stop and hand off to a human.
The Approach
  • Designed as a genuine tool-calling AI agent, not a single prompt or a scripted decision tree — at each step, the agent itself decides which of its tools it needs rather than following a fixed sequence, so it can handle real-world cases that weren't explicitly anticipated.
Input → Decide → Call tool → Read result → Decide next step → Respond
The Agent's Tools
ToolWhat it does
get_panelRetrieves verified part specs — dimensions, material, required operation.
get_workstation_requirementsChecks what a workstation is actually equipped to handle.
search_sopPulls relevant procedure instructions from stored documentation.
record_eventLogs every scan, question, and decision for traceability.
escalate_to_supervisorTriggers a human handoff whenever data can't safely support an answer.
The Core Design Rule
Grounding rule: the agent is instructed to never state a fact it didn't retrieve from a tool, and to cite its source on every answer (e.g. "Source: Panel P-1002"). If the underlying data doesn't support an answer, the agent doesn't guess — it escalates. This single rule is what separates a usable production tool from a demo.
Engineering Challenges (and how I solved them)
  • 🔁 Infinite tool-call loop.

    The agent kept looping until it hit the system's iteration cap. Root cause: one tool was misconfigured to update records instead of insert new ones, so it silently failed every time it ran — and the agent kept retrying a call that could never succeed. Fixed the operation type and added explicit "call once" logic to the agent's instructions.
  • 🔍 Search returning nothing.

    A filter misconfiguration caused a lookup tool to treat the operator's actual question as a database column name instead of a search value — a subtle bug that quietly broke retrieval. Fixed by correcting which field the AI was allowed to control.
  • ⚠️ False-positive confirmations.

    Early on, an unfiltered lookup tool returned all records regardless of input — meaning even a completely invalid part code got "confirmed." Fixed by adding a strict exact-match condition, so unknown inputs correctly return nothing.
  • 📦 Unstructured output.

    Free-text AI responses are hard to route reliably. Added a structured output schema (status, message, source, escalation flag) so the workflow can branch cleanly instead of parsing prose.
Results
ScenarioOutcome
Correct part, correct workstation✅ Verified, grounded instructions returned with source
Part sent to wrong workstation✅ Mismatch caught, processing blocked, correct workstation named
Question outside available data✅ No hallucination — escalated to supervisor
Unknown/invalid part code✅ Clean "not found" response, nothing invented
Conflicting physical vs. system data✅ Recognized as unsafe to resolve, escalated automatically
What This Project Demonstrates
  • Designing genuine agentic reasoning, not a scripted pipeline disguised as one
  • Treating "I don't know — escalating" as a correct, first-class outcome rather than a failure
  • Debugging AI agent behavior methodically — using execution traces to find root causes, not guessing
  • Choosing the simplest architecture that actually works — no vector databases, no multi-agent complexity, no unnecessary infrastructure
Technology Stack: n8n Google Gemini Tool-Calling Agent Architecture Structured Data

🛒 eCommerce Customer Nurture & Retention System

GoHighLevel · self-initiated project

Built in GoHighLevel — automatically re-engages customers the moment they abandon checkout, with zero manual intervention.

The Problem
  • Online stores lose a significant share of revenue to abandoned checkouts — customers who start the buying process but drop off before completing payment. Without automated follow-up, that revenue is simply gone.
The Solution
  • Built an automated nurture and retention workflow in GoHighLevel that re-engages customers the moment they abandon checkout — without any manual intervention from the business owner.
How It Works
  • Triggers automatically the instant a checkout is abandoned.
  • Waits a short window (1 hour) to avoid feeling intrusive, then sends a discount code email to incentivize completion.
  • If the customer still hasn't converted after a day, the workflow continues nurturing with further automated outreach.
  • The entire sequence exits automatically the moment an order is completed — so customers never receive irrelevant follow-ups after they've already purchased.
Abandoned checkout → Wait 1hr → Discount code email → Wait 1 day → Continued nurture → Goal: order complete (exit)
Impact
  • This kind of automation typically recovers a meaningful percentage of otherwise-lost sales, running entirely passively in the background — no manual tracking, no missed follow-ups, and a clean customer experience that adapts in real time to whether the sale actually closes.
Built With: GoHighLevel Workflow Automation Goal-based Exit Logic Multi-step Delayed Email Sequencing

⭐ Review Request Automation

GoHighLevel · self-initiated project

Built in GoHighLevel — a multi-channel review request system that adapts based on how the customer actually responds, not a single blast email.

The Problem
  • Businesses lose out on positive reviews simply because asking for them manually is inconsistent — and worse, an unhappy customer asked for a public review at the wrong moment can turn into reputational damage instead of growth.
The Solution
  • Built a multi-channel review request automation that adapts based on how the customer actually responds — not just a single blast email.
How It Works
  • Sends an automated review request email after a service/purchase.
  • If the customer doesn't respond within a day, the system automatically follows up via SMS instead of giving up — and repeats the reply/timeout logic again to maximize response rate across channels.
  • When a customer does reply, the workflow reads their rating response and branches intelligently: high ratings (4-5) are routed to leave a public review, capturing positive word-of-mouth, while low ratings (1-3) are routed to a private feedback flow instead — protecting the business's public reputation while still capturing the complaint for follow-up.
  • Non-responders are cleanly exited from the sequence rather than spammed indefinitely.
Review request email → No reply → SMS follow-up → Rating branch → 4-5: public review → 1-3: private feedback
Impact
  • This turns review generation from a manual, inconsistent task into a fully automated system that increases positive review volume while actively filtering out public negative reviews — a direct, measurable reputation and revenue lever for local/service businesses.
Built With: GoHighLevel Workflow Automation Conditional Branching Logic Multi-Channel Follow-Up (Email + SMS) Sentiment-Based Routing

📧 Cold Email + SMS Outreach Campaign Workflow

GoHighLevel · Upwork portfolio piece

Turns cold contacts into engaged leads by automatically escalating from email, to SMS, to a real human — so no opportunity ever goes quiet. Published to my Upwork portfolio on Oct 21, 2025.

The Problem
  • Most cold outreach dies after a single unanswered email. There's no consistent system forcing a second touch, a third channel, or a human follow-up — so promising leads go quiet and get written off, not because they weren't interested, but because nobody followed up again.
The Solution
  • Built a multi-touch, multi-channel outreach workflow in GoHighLevel that automatically escalates engagement — starting with email, moving to SMS if there's no response, and finally assigning a manual task to a team member if the contact still hasn't engaged. Every cold contact gets multiple genuine touches before ever being written off.
How It Works
  • Triggers automatically the moment a contact is tagged for cold outreach — no manual list-building or manual sending required.
  • Sends a personalized intro email, then waits a couple of days to give the contact room to respond naturally rather than feeling spammed.
  • If there's no engagement, the workflow automatically sends a follow-up email and, when that also goes unanswered, escalates to an SMS touch — meeting the lead on a channel they're more likely to actually see.
  • If the contact still hasn't responded after SMS, a task is automatically assigned to a team member — so high-value leads never fall through the cracks of pure automation; a real person steps in exactly when it matters.
Cold-outreach tag → Intro email → Wait 2 days → No response → SMS → Still no response → manual task
Impact
  • Turns a one-and-done outreach effort into a persistent, multi-touch sequence that maximizes response rate without any extra manual work — and guarantees that even contacts who don't respond to automation still get a real human follow-up, so no lead is ever silently lost.
Skills & Deliverables: GoHighLevel Automated Workflow Conditional Time-Out Logic Multi-Channel Sequencing (Email + SMS) Automated Task Assignment
